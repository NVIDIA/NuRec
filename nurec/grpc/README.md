# Neural reconstruction engine gRPC server and client definitions

This folder defines the gRPC server and client for neural reconstruction engine. The `.py` files in its root
defines the server and the `.proto` files in `protos/` defines the client, called protobufs. The `.py` and `.pyi`
files in `protos/` are generated by the `update_generated.py` script run via Bazel using the commands:

```
bazel run //nurec/grpc:update_generated
bazel run //:format
```

The commands above should be run anytime the protobufs change as it will update the generated files. The files
should also be committed to the repository to reflect the protobuf changes. Several tests depend on these
generated files.

## Serving modes

`serve-grpc` runs in one of two modes, both exposing the same gRPC API:

- **Single-process (default).** One process serves renders directly (`serve.py`).
- **Multi-process drop-in (`serve-grpc --multiproc-workers N`, `N > 0`).** An owner process holds one
  read-only copy of the weights and shares it over CUDA IPC to `N` worker processes behind a front proxy
  (`multiproc_serve.py`, `model_owner.py`), for MPS-backed throughput scaling. It is a drop-in for the
  single-process API; asset editing and temporal-harmonizer sessions are the two refused capabilities.

See [the gRPC API guide](https://docs.nvidia.com/nurec/api/grpc_api_guide.html) for the full flag set, admission/deployment
semantics, and drop-in migration notes.
Hosted NuRec links track the latest published docs and may differ from this
checkout.

## Customer Distribution

The client protobufs are packaged for customer distribution using the Bazel export target:

```
bazel build //nurec/grpc/release:customer_distribution_tarball
```

This creates a self-contained tarball at `bazel-bin/nurec/grpc/nurec_grpc_protos_customer_dist.tar.gz` that includes:

- Protocol buffer definitions (`common.proto`, `sensorsim.proto`)
- Customer-specific generation script (`update_generated.py`)
- Complete documentation (`README.md`)
- Dependency requirements (`requirements.txt`)
- Proper package structure with `__init__.py` files

### Customer Usage

A customer receiving this package can:

1. **Extract the package:**

   ```bash
   tar -xzf nurec_grpc_protos_customer_dist.tar.gz
   ```

2. **Install dependencies:**

   ```bash
   pip install -r requirements.txt
   ```

3. **Generate Python code:**

   ```bash
   python nurec/grpc/update_generated.py
   ```

4. **Use in their code:**
   ```python
   import nurec.grpc.protos.sensorsim_pb2 as sensorsim_pb2
   import nurec.grpc.protos.sensorsim_pb2_grpc as sensorsim_pb2_grpc
   # ... use the generated gRPC stubs
   ```

The customer distribution is completely self-contained and does not require Bazel or access to the full NuRec codebase.
