# Pre-Built Gaussian Parameter Collector Kernels

This folder contains a list of collector configurations used to generate Slang kernels at build time, generate the associated CUDA code and slangtorch integration Torch extension, compile those and produce a Torch extension that can be loaded faster at runtime to access those kernels.

The files in this folder are generated by running training (or other runs) and setting the environment variable `OUTPUT_CONFIGURATIONS_PATH` to a path where to output the .json file. They must then be copied to this folder and renamed according to the config it represents.

It will then be automatically picked up by the build system when generating the pre-built collector kernel libraries.

## Which configurations a preset produces

A layer's configuration lists its collectors in a fixed order: positions/rotations/scales/densities, then one `Collector_Copy<N>` per non-empty extra-signal group in the order common, camera, lidar (`N` = the summed `n_signal_dim` of that group), then the spherical-features collector. Options that add extra signals therefore change every layer's configuration, and a preset enabling such an option needs its own file even when its layer mix is otherwise identical to an existing one:

- `semantic_logits` (camera, 20) gives the `Collector_Copy<20>` of the `car2sim` family.
- `options/lidar_rendering: intensity_raydrop` (lidar, 1 + 2) adds a `Collector_Copy<3>` after it. `apps__prod__Hyperion-8.1__car2sim_lidar.json` holds these variants; the `sqa_lidar_*` presets (Hyperion-8.1 and PAI) share the same Gaussian layer mix and are covered by it.

Layers with the same collectors share a configuration: in the `car2sim` family the `vehicle_lights` layer (rigid, no temporal appearance) matches the rigid fallback of `dynamic_deformables` and `cones` matches `road`, so six layers yield five configurations.

A configuration that is not in this folder is compiled with `slangc` at runtime (tens of seconds, once per process). `//nurec/models/gaussians/collect:collector_prebuilt_configs_test` checks that the shipped presets are covered.

## Closed-loop GRPO

`apps__AV__NV__closed_loop_grpo.json` names a consumer workload, not a YAML preset.
It prebuilds Car2Sim-family collector signatures for `model.renderer.sh_features_dtype=fp32`,
including the lidar-free step-Fourier variant. The current `3dgut_gsplat` preset uses
`fp16`; the `car2sim` and `car2sim_lidarfree` files cover those variants.

Regenerate this set with `OUTPUT_CONFIGURATIONS_PATH` when the fp32 consumers' layer
or extra-signal settings change. Remove it when no consumers need these fp32 signatures.

## Runtime fallback cache

The generated sources and slangtorch's build directories for runtime-compiled configurations land in the system temp directory. Set `NUREC_SLANG_JIT_CACHE_DIR` to a persistent, writable directory to keep them across process and container restarts. The generated file's name carries a digest of the generated code, the pre-built `collector.slang-module` and the torch version, and slangtorch's own metadata covers its version and compile options, so an image upgrade or rollback compiles into a new file instead of reusing a build made from other inputs, and the compile is paid once per deployment instead of once per process.
