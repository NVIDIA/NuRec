## Rendering-quality metrics

Each KPI compares NuRec's rendered view at held-out poses against the corresponding captured image:

| Metric                                                | What it measures                                                                | Scale / direction                                                                                                           | Notes                                                                                                             |
| ----------------------------------------------------- | ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **PSNR** (Peak Signal-to-Noise Ratio)                 | Per-pixel intensity fidelity, derived from MSE on a log scale                   | dB, **higher is better**; unbounded above. Identical images → ∞; natural-image renders typically fall in the 15-35 dB range | Dominated by low-frequency intensity/exposure error; insensitive to small geometric shifts                        |
| **SSIM** (Structural Similarity Index)                | Local structural similarity (luminance, contrast, structure over small windows) | Range `[-1, 1]`, **higher is better**; `1.0` = identical                                                                    | More robust than PSNR to exposure / tone shifts; sensitive to blur and structural distortion                      |
| **LPIPS** (Learned Perceptual Image Patch Similarity) | Perceptual distance in deep-feature space (pretrained CNN features)             | Range `[0, ~1]`, **lower is better**; `0.0` = perceptually identical                                                        | Best single proxy for "does this look right to a human"; catches texture / detail artifacts that PSNR / SSIM miss |

The NuRec repo does not publish universal pass/fail thresholds for these metrics -- absolute values depend heavily on sensor count, scene complexity, vehicle speed, and exposure, so a scalar cutoff is not meaningful across datasets. Compare against a prior good run of the same sequence (regression) rather than against an absolute baseline; a large PSNR / SSIM drop or LPIPS jump vs. a known-good reference run is the signal to diagnose. Pixel-subsampling shifts which pixels the model optimizes for and will produce different absolute metric values even on an identical converter, so use the same subsampling setting across any run pair you intend to compare directly. This workflow trains at full resolution by default; a run that opted into `batch_sampler_2` or `batch_sampler_4` is not directly comparable to one that did not.

## Container warnings

Three warnings the pinned NuRec and `ncore-aux-data` images emit describe their own trigger inaccurately, and all three appear in the logs of runs that completed. They cannot be reworded here, so each row below gives the condition the message actually reports, whether the run continues, and what to look at instead of what the text suggests. None of them is grounds for an entry in either issue bucket on its own.

| Message                                                                                                                                                                                                                | What it actually reports                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Severity, and whether the run continues                                                                                                                                                                | What to check instead                                                                                                                                                                                                                                                    |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `[NuRec::NRend][WARNING] ::: NRESHGaussianModel : missing parameters tensor <name> in the state_dict.` -- one line per tensor name                                                                                     | Each line names one per-Gaussian parameter tensor the renderer did not find in the state dict. The printed name is the key it looked for, so the leading dot in `<.positions>` shows a key assembled without a layer name.                                                                                                                                                                                                                                                                                                                                                     | Warning-level, and the load is not abandoned -- runs that completed carry the full block. The text does not distinguish a tensor the model was never going to carry from one that is genuinely absent. | Whether the step wrote its artifact. Completed runs carry this block, so on its own it is not evidence that the model failed to load; the output is.                                                                                                                     |
| `NVENC (h264_nvenc) not available on this host - falling back to libsvtav1 (CPU AV1 encode). Expect ~5-10x slower encode time but smaller files. To use NVENC, run on a host with an NVIDIA GPU + NVIDIA driver (...)` | An MP4 write probed the encoder by encoding one 16x16 frame with `h264_nvenc`, and the probe exited non-zero or timed out after 15 seconds. The closing advice is the inaccurate part: the images already request the `video` driver capability, so a working GPU and driver do not make this probe succeed. The usual cause is a GPU with no encode engine at all, which several data-center parts ship without -- check the part against NVIDIA's [Video Encode and Decode GPU Support Matrix](https://developer.nvidia.com/video-encode-and-decode-gpu-support-matrix-new). | Informational, logged once per output directory. Every MP4 is still written, by CPU AV1 encode instead.                                                                                                | Whether the videos play. They are valid MP4 carrying AV1, so a player without AV1 support shows nothing for a file that is intact. Encoding is the only thing that got slower; reinstalling a driver or moving hosts fixes nothing unless the new GPU has an encoder.    |
| `Video width not multiple of 16 - ffmpeg will warn about unaligned data`                                                                                                                                               | Frame **height** is not a multiple of 16. The check behind this message reads the height and the text names the width, so it fires on frames whose width is a clean multiple of 16 and stays silent when the width alone is unaligned.                                                                                                                                                                                                                                                                                                                                         | Informational, and the video is written.                                                                                                                                                               | Nothing for the alignment itself. The same writer does drop the last row of odd-height frames and the last column of odd-width frames, so a video built from odd-dimensioned frames is cropped by a pixel; quality metrics come from a separate path and are unaffected. |

## NCore-related reconstruction failure mapping

| Symptom                                                                                                         | Likely NCore cause                                                                                                                                                                                                                                                                                                                                                               | Fix area                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "No valid rays" warnings                                                                                        | Masks blocking all pixels, bad calibration/intrinsics, or wrong camera-to-rig pose                                                                                                                                                                                                                                                                                               | masks, intrinsics, `T_camera_rig`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Low PSNR across **all** cameras                                                                                 | Coordinate frame mismatch or broken pose trajectory                                                                                                                                                                                                                                                                                                                              | rig frame, `T_rig_world`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Low PSNR on **specific** cameras                                                                                | That camera's intrinsics or extrinsic is wrong                                                                                                                                                                                                                                                                                                                                   | per-camera `T_camera_rig` and model params                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Training crashes on data loading                                                                                | `sequence_meta` paths incorrect, component stores missing                                                                                                                                                                                                                                                                                                                        | `.json` meta paths, volume mounts                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| NaN losses                                                                                                      | Extreme pose values, degenerate geometry, bad transforms                                                                                                                                                                                                                                                                                                                         | pose values, non-finite checks                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Blurry renders                                                                                                  | Rolling shutter not modeled, or timestamps inaccurate                                                                                                                                                                                                                                                                                                                            | `ShutterType`, camera timestamps                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| LiDAR not contributing                                                                                          | LiDAR component not found or model_element issues                                                                                                                                                                                                                                                                                                                                | LiDAR intrinsics, `T_lidar_rig`, `model_element`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Training crashes (exit 255) on a LiDAR FOV-validity check (stored beam directions fall outside the model's FOV) | Caught pre-flight by the `check_lidar_model_fov_consistency` hard error; if this crash still occurs, ensure validation was run first. Root cause: stored direction encodes per-ray geometry the model parameters do not: non-zero per-beam offset Δ but `row_azimuth_offsets_rad = 0`, OR `column_azimuths_rad` is a rotor-phase-only schedule too coarse to host `(rotor + Δ)`. | Route to [build-ncore-converter/conventions.md row_azimuth_offsets_rad guidance](../build-ncore-converter/conventions.md#lidar-model-parameter-source-hierarchy). Pattern 1 (Sensor-native + Preserve) when the sensor publishes a Δ table and the rotor schedule is recoverable; Pattern 3 (Synthetic-uniform + Encode-in-column) when the native rotor schedule cannot be cleanly recovered (rotor-phase-only stream, dual-return / near-field run patterns, or `\|Δ\| >` native column step). See the routing block in SKILL.md for the full `suggested_fix`. |

## NuRec config-selection failure mapping

Goes into `nurec_config_issues`. Each row lists the `suggested_fix.kind` / `value` the workflow's config-fix loop can apply directly:

| Symptom                                                                                     | Likely config cause                                                                                                                                    | `suggested_fix`                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Dynamic objects absent from renders while shard contains dynamic cuboids                    | Authored config inherits a `_base_3dgut_static.yaml` base when a dynamic variant was required                                                          | `custom_config_edit`, swap the inherited base in the SQA recipe (`/apps/AV/_base_3dgut_dynamic.yaml`) and re-launch                                                                                                                                                                                                                                   |
| Cuboids ignored by training despite being in the shard                                      | The authored config's `label_classes` allow-list excludes the shard's class IDs                                                                        | `custom_config_edit`, extend `label_classes` to include the observed IDs (or, if the shard's naming is wrong, route as a converter issue instead)                                                                                                                                                                                                     |
| Cuboids dropped by `track_label_sources` gating                                             | Authored config still restricts `dataset.cuboid_tracks_params.track_label_sources` (e.g. left unset and inheriting `[AUTOLABEL]` from a dataset mixin) | `custom_config_edit`, set `dataset.cuboid_tracks_params.track_label_sources: null` in the custom config (or pin to the sources actually present in the shard)                                                                                                                                                                                         |
| `"Requested cameras not present in the data: <id>"` at launch                               | Authored `dataset.camera_ids` doesn't match the shard, e.g. a stale list left over from a prior dataset                                                | `custom_config_edit`, set `dataset.camera_ids` / `dataset.lidar_ids` in the custom config to the shard's actual sensor IDs from the sequence meta JSON (operator-supplied list takes precedence)                                                                                                                                                      |
| `"multiple lidar sensors per batch is not supported for now"` assertion during data-loading | Authored `dataset.lidar_ids` contains more than one entry (NuRec trains on a single LiDAR per run)                                                     | `custom_config_edit`, set `dataset.lidar_ids: [<single selected LiDAR>]` per the `nurec_lidar_selection` policy                                                                                                                                                                                                                                       |
| Validation MP4s play too fast or too slow                                                   | Authored `system.test.video_fps` inherited a bundled default instead of the shard's effective camera cadence after `dataset.val_camera_frame_step`     | `custom_config_edit`, set `system.test.video_fps` to the effective input camera FPS after `dataset.val_camera_frame_step` and re-launch                                                                                                                                                                                                               |
| Out-of-memory during LiDAR batch assembly                                                   | Available GPU memory is below what the selected config requires                                                                                        | Not fixable by `nurec-onboard`. Record the OOM, the available GPU memory, and refer the operator to NuRec's _Hardware Requirements_ (minimum 24 GB GPU memory, 48 GB recommended) and _Run on Multi-GPU Systems_ guide (`trainer.world_size` / `trainer.num_nodes`). Also revisit `nurec_lidar_selection` if the selected LiDAR is a short-range unit |

## label_classes extension template

For the "Cuboids ignored by training" row above. The bundled `dynamic_gaussians.yaml` `label_classes` list does not cover every dataset's `class_id` vocabulary; class IDs not in any layer's list are silently dropped. The SQA recipe in SKILL.md already includes a `model.layers.dynamic_rigids.tracks.label_classes` block (and the deformable equivalent) -- the fix is to extend those lists with the shard's observed IDs. NuRec replaces YAML lists rather than merging, so paste the **full** bundled default list verbatim from `configs/model/gaussians/composite/dynamic_gaussians.yaml` and append the shard-specific extensions; truncating the list silently drops the bundled vocabulary.

Enumerate observed `class_id` values via [the dynamic-vs-static probe](SKILL.md#select-or-create-app-config) (`set(observation.class_id for ... in CuboidsComponent.Reader)`), then append them. Class-id strings are case-sensitive and must match the shard exactly. If the shard's naming itself is wrong (e.g. typo, abbreviation that should be a canonical name), route as a converter issue (`ncore_data_issue`) instead of patching the config.
