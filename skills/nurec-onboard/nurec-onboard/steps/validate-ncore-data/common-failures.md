## V4 Structure failures

| Failure message                                 | Root cause                                       | Fix location       | Fix                                                                                                                                                                                                              |
| ----------------------------------------------- | ------------------------------------------------ | ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sequence_id is empty`                          | `get_sequence_ids` returns empty strings         | `get_sequence_ids` | Return non-empty sequence identifiers from your data source                                                                                                                                                      |
| `version is '<X>', expected 'v4'`               | Stale or manually edited sequence meta           | `convert_sequence` | Ensure `SequenceComponentGroupsWriter` is invoked correctly (it sets version automatically)                                                                                                                      |
| `sequence_timestamp_interval_us (start < stop)` | Zero-length or inverted interval                 | `convert_sequence` | Verify `t_start_us < t_end_us`; use `HalfClosedInterval.from_start_end(t_start_us, t_end_us)` (the constructor treats `end` as inclusive and adds `+1` internally -- passing `+1` yourself causes an off-by-one) |
| `no rig→world dynamic pose found`               | `_write_poses` missing `store_dynamic_pose` call | `_write_poses`     | Add `poses_writer.store_dynamic_pose(source_frame_id="rig", target_frame_id="world", poses=T_rig_worlds, timestamps_us=timestamps_us)`                                                                           |
| `rig→world dynamic timestamps outside interval` | Pose timestamps don't span `[start, stop-1]`     | `_write_poses`     | Ensure `timestamps_us[0] == interval.start` and `timestamps_us[-1] == interval.stop - 1`                                                                                                                         |

### Near-range cuboid LiDAR overlap — demotion criteria

`check_cuboid_lidar_overlap` fires as **`converter_issue`** by default. Demotion
to `input_data_issue` (limited-FoV LiDAR sensor) requires **all** of the
following checks to pass; record each verbatim in `notes` — any miss keeps the
classification as `converter_issue`:

1. `model_angular_error_max_deg` < 0.5° (model self-consistency passes).
2. `warn_lidar_forward_ray_rig_axis_residual` does **not** fire (worst cardinal
   model azimuth in `{0, π/2, π, 3π/2}` projects to its expected rig direction
   within ~14°).
3. `element_coverage_pct` is 20–35% **and** `data.docs` documents the LiDAR as
   short-range / limited-FoV.
4. AABB hit rate over near-range cuboids is high (OBB inlier ratio alone is
   **not** sufficient).

## Eval metric red flags

| Metric                              | Bad value                                           | Likely cause                                                                                                                              |
| ----------------------------------- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `rate_hz` = 0                       | No dynamic poses, or timestamps all identical       | Check `_write_poses` timestamp derivation                                                                                                 |
| `rig_forward_alignment` << 1.0      | Coordinate frame mismatch                           | Rig +X is not forward; apply a rotation to the pose trajectory                                                                            |
| `total_displacement_m` = 0          | Vehicle stationary or poses all identical           | Verify pose source data actually contains motion                                                                                          |
| `frame_balance` << 1.0              | One camera has far fewer frames                     | Check camera data loading; missing files?                                                                                                 |
| `model_angular_error_max_deg` > 0.5 | Directions don't match model grid                   | Check `model_element` row/col derivation, or verify LiDAR intrinsic parameters                                                            |
| `intensity_completeness` << 1.0     | Many points missing intensity                       | Check if source format stores intensity in a different field name                                                                         |
| `element_coverage_pct` ~ 0          | Almost no model grid elements observed              | LiDAR may be solid-state (not spinning), or `model_element` derivation is wrong                                                           |
| `element_coverage_pct` 20–35%       | Short-range (SR) or limited-FOV LiDAR               | **Expected** for sensors that only cover a fraction of the spinning grid. Not a converter bug -- confirm against the sensor's stated FoV. |
| `clock_consistency_ratio` << 1.0    | Cameras and ego trajectory not time-aligned         | Timestamp conversion error or clock sync issue                                                                                            |
| `temporal_overlap_pct` << 100       | Camera and LiDAR timestamp ranges have poor overlap | Check that all sensors span a similar time range                                                                                          |
